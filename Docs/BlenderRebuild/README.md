# Blender reconstruction work

The active objective is to rebuild the full SourceAssets/Voxel collection in Blender to match the supplied concepts and integrate the resulting physical models and materials into Unreal. Earlier Unreal build receipts are not visual approvals. No item is currently marked as having perfect fidelity.

The inventory is generated from the actual 77 PNGs by `Scripts/BlenderRebuild/catalog.py`. Object concepts, material swatches, animation/view associations, and the lodge's contact-shadow reference remain explicitly tracked. Texture revisions must be reviewed as materials; producing another textured slab alone does not meet the objective.

All 33 currently authored Blender outputs (26 source concepts and seven placement variants) now open as normal editable projects with their own active scene and camera. The earlier `libraries.write` outputs could start in an empty scene when opened directly. `package_blend.py` now packages each isolated scene in a fresh Blender process, and `verify_opened_blend.py` checks the actual file in another independent process. Every current file hash, active scene/camera, authored part count, packed image count, exported triangle count, material count and UV-layer count is recorded in `project-packaging-verification.json`. Cottage legitimately uses one packed atlas; the other current outputs use three. This repairs source usability without granting visual acceptance.

The preceding interactive readback crashed Blender 5.2.1 in `bpy.data.user_map`. It has been replaced with independent process readback; the new export-and-reopen path was exercised through Blender MCP on Moss Tonic. The project launcher recovers the already installed Lab extension in process-local preferences after restart. The recovered MCP session is connected to the actual MossTonic.blend project. No global Codex MCP entry or saved global Blender preference was added.
